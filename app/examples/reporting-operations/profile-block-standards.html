Maintenance guide

Profile Block Standards

How to name and look after the profile blocks in about/_profile-blocks on the PROVOST-VPAA-PROVWEB site, so the next person who edits them can follow one pattern.

Based on the block relationship report generated 1 October 2026. Counts quoted below come from that report and will drift, so re-run the report before acting on them.

Naming standards

  1. Lowercase letters, numbers and hyphens only

    No capitals, spaces, underscores or accented characters. Names then sort the same everywhere and are safe in URLs and scripts.

    Today: 33 names start with a capital letter and one contains an accent.

    Usegee-cieguerra-norma
    AvoidGee-CiéGuerra-Norma

  2. Surname, then given name: lastname-firstname

    The hyphen separates the surname from the given name and nothing else. Join compound surnames and compound given names without hyphens.

    Today: 106 of 126 names already follow the two-part pattern. 20 have three or four parts.

    Useramosharwood-roelhowardrappaport-debbie
    Avoidramos-harwood-roelGarza-John-David

  3. Name the person, not the page, year or position

    No page names, numbers or years in the name. Someone's seat, page or list order changes, and then the name is wrong. Set the display order on the page instead of in the block name. An office that changes hands, such as sga-president, may be named for the office.

    Today: -personnel suffixes on two blocks, wilkerson-steve26, and 14 numbered blocks in _academic_council where numbers 04, 08 and 11 are missing from the sequence.

    Usemeersman-katietrepal-heather
    Avoidmeersman-katie-personnel12-trepal-heatherwilkerson-steve26

  4. One block per person, attached wherever it is needed

    If someone appears on more than one page, attach the same block to each page. Do not copy it. Give each person one home folder, based on their main role. Editing the one block then updates every page.

    Today: wilkerson-steve, cigarroa-francisco, halbesleben-jonathon and xiong-jinjun each exist in two folders. Del-Toro-Debra and deltoro-debra-personnel look like the same person, and so do meersman-katie and meersman-katie-personnel. In each pair one block is in use and the other is not.

Profile photo standards

Size 340 × 400 px

Portrait, 340 pixels wide by 400 pixels high. Crop to this size before uploading so every profile on a page lines up.

Resolution 72 ppi

The standard web resolution. Pages use the pixel size, so 72 ppi is the setting to export with and not a reason to enlarge the image.

File name lastname-firstname

Name the photo file the same as the block it belongs to, following the naming standards above.

Maintenance practices

  • 1. Treat "Unused" as a lead, not a verdict

    The report only shows relationships Cascade has recorded. A format or template that pulls a block in by path will not appear. Before removing a block, search the site's formats for its path and ask the page owner. Then delete it to the recycle bin, not permanently, and leave it there for a full term.

  • 2. Remove people from the page first, then the block

    When someone leaves a role, take them off the page, re-run the report, and delete the block once it shows Unused. 61 of 126 blocks (48%) are unused today. Some are likely people who have left, and some are duplicates.

  • 3. Edit in place; create new blocks by copying a clean one

    To change a name, title or photo, edit the existing block. To add a person, copy the profile base asset (or a clean block if there is no base asset) and then rename it to follow the standards above. This is the copy, read, edit pattern from chained-operations/07.create-from-base-asset.html. Rename with Move instead of deleting and recreating, then re-run the report and check formats that mention the old path.
